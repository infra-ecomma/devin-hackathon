# Onboarding UX

_Design first-run flows that reach users' aha moment (first success) as fast as possible—every screen either teaches or moves toward value._

**CATEGORY** Skills · Design  •  **TRIGGER** `onboarding`  •  **RATING** ★★★★☆ (8/10)  •  **STATUS** Curated

---

## Why It Earns the Curated Bar

- **Aha-moment first**: Every onboarding decision is justified by "does this move the user closer to their first success?" not "is this a nice feature?"
- **Empty states as primary surfaces**: Treats empty states as critical design moments, not afterthoughts—they're where new users first see the product's potential.
- **Friction elimination**: Removes every unnecessary step between sign-up and first value; progressive disclosure reveals complexity only when needed.

## What It Does

This skill designs first-run experiences focused on one goal: reaching the user's aha moment (first personal experience of core value) as fast as possible. It starts by defining the aha moment explicitly: "Slack users realize 'my whole team is actually here talking'," "Notion users discover 'I can structure this exactly how I think.'" Then it maps the onboarding flow backward from that moment: what must be true for the aha to happen?

(team invited, initial message sent; workspace created, first block added). Empty states become primary design surfaces where new users first see the product's potential—not blank pages.

Welcome flows are minimal friction; guided tours use contextual tooltips to teach, not interrupt. Progressive disclosure is key: show only what's needed at each step.

A new user doesn't need all settings; they need to reach their aha moment. Once they've had success, show advanced options.

## How to Use

1. **Define the aha moment**: Specify the exact action/insight that makes a new user realize the product's value.
2. **Map the prerequisite path**: Work backward from aha to first login—what must happen?
3. **Design empty states**: These are onboarding surfaces; make them inviting, not blank.
4. **Eliminate friction**: Every step must move toward the aha moment or teach something essential.
5. **Use progressive disclosure**: Show advanced features only after first success.
6. **Test with real new users**: Watch actual new users try the flow; where do they get stuck?

## What NOT to Do

- Do not skip aha-moment definition; without it, onboarding is a guess.
- Do not hide empty states in edge case handling—they're the first surface new users see.
- Do not force users through mandatory tutorials if they can reach the aha moment without them.
- Do not test onboarding with existing users (they'll skip things); test with real new users who've never used the product.
